## Design and implementation

In this example, you have to provide a pre-trained NN model with weights, regression data, and model parameters. The DEEPCRAFT&trade; Model Converter tool can generate such data in the standard Keras H5, TFLite, or PyTorch format. By default, these files are located in the *./deepcraft* folder for each core project (*proj_cm55* and *proj_cm33_ns*). The code examples also provide a DEEPCRAFT&trade; Model Converter project file *project.byom* for each core project, which points to the pre-trained NN model available in the *pretrained_models* folder.

If you change the output file location in DEEPCRAFT&trade; Model Converter, reflect the change to the `NN_MODEL_FOLDER` parameter in the *Makefile* file as well. The model data is stored in *.c*/*.h* files (used for filesystem applications). Depending on the type of NN model chosen using the `NN_TYPE` parameter in *Makefile*, the application uses the files and variables from the following table, where 'KEY' refers to the *Output File Name* defined by DEEPCRAFT&trade; Model Converter:

**Table 1. DEEPCRAFT&trade; output files**

Folder name                | File name | Description
:--------                  | :-------- | :------------ 
*deepcraft*                | *KEY__int8x8.h/c* <br> *KEY_float.h/c* | Contains the NN weights and biases
*deepcraft/eval_data*      | *KEY_int8x8_data_input.h* <br> *KEY_int8x8_data_output.h* <br> *KEY_float_data_input.h/c* <br> *KEY_float_data_ouput.h/c* | Contains the input and output regression data

<br>

DEEPCRAFT&trade; Model Converter supports quantizing data while deploying an int8x8 model. To do this, select **Force Float32 API Input/Output**. The `IMAI_compute` function then takes in floating point data, which is then automatically quantized before passing it to the model, the output is dequantized automatically.

In *Makefile*, set the `NN_MODEL_NAME` parameter based on the *Output File Name* chosen in the DEEPCRAFT&trade; Model Converter tool.

After updating *Makefile*, all model files are built into the application automatically, allowing the NN inference engine to be initialized and fed with regression data.

By default, the CM33 application places the model weights in the SRAM and the CM55 application places the model weights in the SoCMEM for best performance. The files generated by DEEPCRAFT&trade; Model Converter let you place model weights and tensor arena by setting specific defines in *Makefile*. The application *Makefile* then uses `CY_ML_MODEL_MEM` to set the location for the model weights, while using `CY_ML_ARENA_MEM` sets the location for the tensor arena.

> **Note:** Some devices among the supported kits may not have enough memory to run some of the configurations listed earlier, particularly when using local regression data. If this occurs, select a different kit with a larger memory device or reallocate memory in the device configurator.
   
<br>

When profiling is enabled, the report includes the average CPU cycles, peak CPU cycles, and peak CPU frame. If an NPU is used, the average NPU cycles, peak NPU cycles, and peak NPU frame are included.

The application automatically loads the regression data generated by the DEEPCRAFT&trade; Model Converter tool, which consists of inputs and outputs. After processing the input data, the inference engine generates the result. The firmware then compares the result with the desired output. If these conditions are met, the firmware contributes to the accuracy calculation.

### Enabling DEEPCRAFT&trade; model profiling

Profiling is enabled by defining `IMAI_PROFILING` in the application *Makefile*.

To get timing results for each model, implement a function named *IMAI_hook_region*. There is an example of this function in the model source file. The funtion needs to interact with a timer or sys_tick which the DEEPCRAFT&trade; flow uses to keep track of the model runtime.
